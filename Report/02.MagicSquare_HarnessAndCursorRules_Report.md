## 3. 아키텍처 결정

### 3.1 ECB 의존 방향

```
boundary → control → entity
```

- **entity**: 10선 합 34 판정 등 순수 도메인. I/O·오류 코드(E001~E005) 비접촉.
- **control**: entity 호출 + 유스케이스; CLI/포맷 없음.
- **boundary**: 입출력, CLI, E001~E007 매핑.

### 3.2 Dual-Track TDD

| Track | Layer | tests/ | Mock |
|-------|-------|--------|------|
| Logic | entity, control | `entity/`, `control/` | Domain Mock **금지** |
| UI | boundary | `boundary/` | 입출력 Mock **허용** |

### 3.3 도메인 확장 (Report/01 대비)

Report/01은 **10선 검증(Verifier)** 중심이었다. 본 Harness·`.cursorrules`는 **부분 마방진 풀이 출력**까지 포함한다.

| 항목 | 정의 |
|------|------|
| 입력 | 4×4 격자, `0`=빈칸(정확히 2개), `1~16` 각 1회 |
| 성공 출력 | `int[6]` = `[r1, c1, n1, r2, c2, n2]` (1-index) |
| 마법 합 | 34 (MagicConstant SSOT 예정) |
