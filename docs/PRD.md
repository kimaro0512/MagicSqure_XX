## 1. 개요

### 1.1 주제 (한 문장)

**4×4 부분 마방진을 “다 맞췄다”고 판단하기 전에, 행·열·대각선(2개) 합 34 검증을 빠짐없이 돌릴 수 있는 판정 규칙과 테스트 루프만 만든다.**

### 1.2 배경 (Mom Test)

| 항목 | 내용 |
|------|------|
| **페르소나** | 4×4 부분 마방진(빈칸 2개, 1~16, 합 34)을 손으로/코드로 다루는 학습자 |
| **진짜 문제** | 행·열·대각선 중 하나라도 검증에서 빼먹으면, “완료” 판정 후 시간을 쓰고, 틀림이 드러나면 그 시간이 헛수고가 됨 |
| **증거** | "지난주 OO 과제에서" / "빈칸 2개…" / "대각선 하나를 빼먹어서 20분 날렸다" |

### 1.3 이번 릴리스에서 하지 않을 것

| 금지 (표면 문제) | 이유 |
|------------------|------|
| 마방진 자동 생성·솔버 | 풀이가 아니라 **판정**이 우선 |
| GUI / 웹 / 모바일 | 검증 패턴을 테스트로 재현 |
| MagicSquare_XX 전체 완성 | 세션 3는 Rule·Command·Test Loop만 |

## 2. R-G-I-O

| | 내용 |
|---|------|
| **Role** | **Verifier** — “맞췄는지” 판정만 담당하는 코드·테스트 |
| **Goal** | 4×4 격자에서 **행 4 + 열 4 + 대각선 2 (10선)** 이 모두 합 34인지 확인; 하나라도 어긋나면 **False** |
| **Input** | `4×4` 정수 격자 — 빈칸 `0`, 채운 칸 `1~16` |
| **Output** | `True` (전부 합 34) / `False` (하나 이상 불일치). *(선택)* 어느 줄이 틀렸는지 |

## 3. 기능 요구사항

### 3.1 Rule (판정 규칙)

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| R-01 | 4×4 격자만 처리 | P0 |
| R-02 | 각 **행 4개**의 합 = 34 | P0 |
| R-03 | 각 **열 4개**의 합 = 34 | P0 |
| R-04 | **대각선 2개**의 합 = 34 | P0 |
| R-05 | 빈칸(`0`)은 합 계산에 포함 | P0 |
| R-06 | 10선 중 하나라도 ≠ 34 → 실패 | P0 |

### 3.2 Command (실행)

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| C-01 | `pytest` 로 검증 테스트 일괄 실행 | P0 |
| C-02 | *(선택)* `python -m magicsquare verify` 등 한 줄 실행 | P2 |

### 3.3 Skill (선택 — 재사용 함수)

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| S-01 | `verify_lines(grid) -> bool` — 10선 전부 합 34 판정 | P1 |
| S-02 | *(선택)* `failed_lines(grid) -> list` — 틀린 줄 식별 | P2 |

### 3.4 Test Loop (TDD)

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| T-01 | Red → Green → Refactor: 행 합 테스트 | P0 |
| T-02 | 열 합 테스트 | P0 |
| T-03 | 대각선 2개 테스트 | P0 |
| T-04 | **회귀**: 행·열만 맞고 대각선 1개 틀린 케이스 → **반드시 실패** | P0 |

## 7. 테스트 시나리오 (초안)

### 7.1 통과 케이스

- 완성된 4×4 마방진 (1~16, 합 34, 10선 모두 만족)

### 7.2 실패 케이스 (Mom Test 회귀)

- 행·열은 34, **대각선 1개만** ≠ 34
- OO 과제형: 빈칸 2개 포함, 채운 후 10선 중 1개 누락 검증 시나리오

- 실제 OO 과제 격자 값
